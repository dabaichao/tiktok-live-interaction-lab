# 抖音游戏运营后台

## 入口与操作

- 后台：`http://127.0.0.1:3002/douyin-admin/`
- 后台与游戏分屏：`http://127.0.0.1:3002/douyin-split/`
- 纯游戏画面：`http://127.0.0.1:3002/test-word-game/`

页面按「直播连接」「礼物库」「互动规则」「游戏设置」「测试与执行记录」分区。
观众画面继续复用原游戏，不显示运营表单。

首次启动先扫码，再填写直播间并连接。登录助手不是开放平台 OAuth，只是本机独立网页登录窗口。

- **停止数据**：停止采集、取消待投递互动，不清除已获取的登录态。
- **切换直播间**：复用登录态；清空上一房间的游戏积分、猜词和统计。房间礼物目录、执行记录相互隔离。
- **同一直播间重连**：保留本场游戏，取消旧连接尚未完成的互动任务。
- **退出账号并断开**：清除内存登录态和本机加密缓存，同时断开直播；缓存删除失败会显示失败，不冒充退出完成。
- **服务进程重启**：自动解密恢复已保存登录态，不重复打开扫码窗口。首次升级前没有保存过的账号仍需扫码一次。

账号状态显示“保留登录字段”不等于平台仍承认该登录；是否收到真实礼物，仍以实际消息为准。
直播期间应保持发起连接的后台页面打开。

### 记住登录（2026-09-18）

Webcast 登录 Cookie 使用 Windows DPAPI `CurrentUser` 加密，不在项目目录保存解密密钥；只维护本机一个账号的当前凭证，不保留历史账号 token 列表。恢复依赖当前 Windows 账号，不能把缓存文件当作可分享的登录包。官方小玩法 Access Token 的保存方式不在此次改造范围内。

- 后台显示已加密保存、已恢复、已到期、需要重新登录或保存失败；状态接口从不返回 Cookie 或密文。
- 登录助手仅通过私有 IPC 交付适用于直播域名的 Cookie及已知到期时间；窗口仍使用临时隔离会话，关闭时清理，不读取个人浏览器资料。
- 已知 Cookie 到期或固定抖音上游明确返回 HTTP 401 时，停止使用旧凭证并提示重新扫码；网络错误、403、直播结束、无礼物不会自动清空登录态。
- 未声明到期时间的会话不伪造有效期；平台有效性仍以连接结果为准，缓存恢复不等于平台认证通过。
- 上游更新的 Cookie 会重新加密保存。退出/换账号后的旧请求不能回写旧凭证；保存和清除按顺序完成。
- 加密或写入失败不降级成明文：当前内存凭证可能仍可使用，但后台明确提示重启后需扫码。缓存损坏、无法解密时不自动恢复。
- 目前加密后端仅支持 Windows；其他系统安全保存不可用时会明确报错，不宣称持久化成功。

原理参考：[Microsoft DPAPI CurrentUser](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dataprotectionscope)。

## 礼物库

目录按房间保存，提供名称/ID 搜索、来源筛选、是否有专属规则筛选、价格排序，以及从礼物卡片直接配置规则。

来源含义：

| 来源 | 含义 |
| --- | --- |
| 平台目录 | 当前非官方接口返回的列表；不保证完整，也未逐项验证房间可赠送资格 |
| 直播实收 | 实际收到过的礼物，不代表完整清单 |
| 手动导入 | 运营人员上传的礼物信息，价格应自行核实 |

同步需先解析到真实房间 ID。平台拒绝、缺少登录、网络失败、空列表或协议改变时显示失败，
保留已有目录，不生成虚假礼物。平台同步未通过真实账号验收时，不应宣传为全量可用。

支持上传 JSON 数组或 `{"gifts":[...]}`，例如：

```json
[
  {"id":"真实礼物ID","name":"小心心","price":1,"icon":""},
  {"id":"另一个真实礼物ID","name":"礼物名称","price":20,"icon":"https://可信图片域名/图标.png"}
]
```

礼物按 ID 匹配，不按名字猜测。未知价格可以省略，价值倍率效果不会用“1”冒充。
价格以当前数据通道的单位为准：Webcast 为平台提供的礼物价值；官方回调现有适配器使用 `gift_value` 的分值。
两种通道的数值**不能当作相同币种**，切通道时应重新检查价值倍率规则，或使用按份/按事件固定数量。
最多导入 10000 种；页面上传限制 1.5 MB；图标只接受 HTTPS。

## 互动规则

本版规则是**抖音全局规则**，换房沿用；不是每个房间独立预设。不会改写 TikTok 的规则或游戏设置。

每个事件只选择一条启用规则：

1. 指定礼物 ID。
2. 包含该单价的价格区间；重叠时列表靠前者优先。
3. 该事件的默认规则。

选中的规则可以独立勾选随机词、加时、解锁提示，也可以显式组合。
启用且没有效果的规则表示“仅展示/记录”；禁用后会继续查找兜底规则。

计算方式：

- 按数量：每份礼物 × 数量；点赞则为每累计阈值的一次触发。
- 按总价值：单价 × 礼物数量 × 倍率，只用于礼物。
- 按事件：整笔结算一次固定数量。点赞未达到累计阈值时不触发。

例如单价 20、数量 3、随机词倍率 10，应发 600 词；不是 200 词。
连击进度不产生游戏效果，最终结算按连击组去重。没有组号时以消息 ID 去重；
无法保证将平台不同 ID、没有组号的重复消息识别为同一礼物。
无用户冷却；点赞按真实 `count` 累计，不用房间总点赞差值伪造用户点赞。

默认规则：

- 每个实际点赞 → 1 个本地随机词。
- 礼物总价值 × 10 → AI 随机词。
- 默认不附带加时、解锁提示。关注和分享默认不配置效果。

关注/分享效果只有通道实际提供该类事件时才能生效。Webcast 社交消息保留 action，
1 映射关注、3 映射分享，未知动作仅记录，不伪装成关注。实际接收仍需直播间验收。

## 游戏设置

可以开始新局、暂停、继续、跳过当前局；在设置中选择词库/题目库、语言、固定答案或题库轮换、
时长、方向提示、阶段提示、奖励积分和模型路由。自定义方向提示只用于固定答案，不能直接包含答案。
猜词继续按本轮答案的字数校验。

模型路由支持固定模型或优先模型＋兜底列表，不限定 hy3。密钥仍从本机环境变量读取，
不会回传给后台或写入运营配置。模型每批最多 100 词，实际批量取后台设置。

AI 不足时是否使用本地补足由设置控制，默认关闭。榜单词汇和执行记录区分 AI 与本地来源。
随机词不会自动猜中答案。生成任务在切房、切题、暂停或停止数据后失效；
正在进行的网络请求可能等到返回才退出，但结果不会再投递到游戏。

游戏设置保存会新开一局并保留本房间积分；切换直播间则清零。
多个页面编辑同一配置时，旧版本保存会被拒绝，避免无提示覆盖。
刷新数据不会覆盖正在编辑的游戏表单；可用“重新读取游戏设置”丢弃草稿并重新加载。

词典文件继续采用项目标准概念词典包，可上传词库或题目库。字典资源目录共享，
但新上传包不会自动更改 TikTok 当前选择的词库。

## 执行记录与隔离预演

“隔离测试”只运行规则计算，不调用模型、不生成直播事件、不改积分或真实记录，
也不消费任何观众的点赞累计值。

真实执行记录显示应发词数、实际完成词数、AI/本地分别完成数量、实际加时和提示数量，
以及排队、执行、完成、部分完成、失败、取消等状态。缺额不被冒充为成功。
页面显示内存保留的当前房间最近记录（最多 100 笔）；服务内存总计保留最新 200 笔。
更早记录保存在本机日志，而不是无限拉长页面。

## 文件与兼容

- `data/douyin/operations.json`：互动规则、游戏/模型设置、提示奖励、常用直播间。原子写入同一文件。
- `data/douyin/gift-catalog.json`：各房间礼物目录。
- `data/douyin/executions.jsonl`：执行日志；到 10 MB 后归档为 `executions-时间-唯一ID.jsonl`，不删除旧档。
- 以上运行数据均被 Git 忽略，不包含 Cookie 或密钥。
- `data/douyin/login.dpapi.json`：单独的加密登录缓存，不是运营配置；已加入 Git 忽略，原文不写入磁盘、参数、日志或前端存储。
- 第一次使用会复制旧后台配置作为初始值；之后抖音设置独立保存。旧版 `data/douyin/admin-config.json` 仅作迁移来源。
- 配置损坏时停用互动规则并提示，自动保存常用房间不会覆盖损坏的原配置。
- 重启后未完成记录标记取消，不自动补发到新局；启动仅读取当前日志的有界尾部，旧档仍保留。

服务/API 的访问限制仍为本机同源。不要把后台直接暴露到公网。
